Why Offline

Why LAN Instead of Cloud?

Traditional platforms depend on internet connectivity — which introduces cheating vectors, reliability issues, and ongoing costs.

❌ Cloud Problems

  • 🔍 Participants can search Google
  • 🤖 Participants can use ChatGPT
  • 🌐 Internet reliability is a dependency
  • 💰 Hosting costs keep adding up

✅ BYTEARENA Solution

  • 🔒 Contest exists only on LAN
  • ⚡ Disconnect Wi-Fi → contest disappears
  • 📦 Zero hosting infrastructure
  • 🆓 Completely free to run
Architecture

How It Works

A clean client-server architecture with a decoupled judge worker for scalable, isolated code verification.

🖥️ Contest Server

Handles authentication, contest timer, problem distribution, submission intake, leaderboard generation, organizer dashboard, and WebSocket push for live updates.

⚖️ Judge Worker

An independent service that picks submissions from a queue, compiles the code, runs hidden testcases, compares output, and returns a verdict — scalable to multiple workers.

📤 Submission Pipeline

Submit → Queue → Judge → Compile → Run tests → Compare → Verdict → Leaderboard update. End-to-end in under 2 seconds with 4–8 workers.

Security

Anti-Cheating Strategy

Rather than relying on impossible browser restrictions, BYTEARENA combines multiple practical layers that together create a fair contest environment.

Layer 1

📡 LAN Isolation

Contest exists only inside the local network. Disconnect from Wi-Fi and the entire contest disappears.

Layer 2

💓 Heartbeat

Browser sends POST /heartbeat every few seconds.

Layer 3

📋 Browser Events

Tab switches, window blurs, and fullscreen exits logged live on the organizer dashboard.

Layer 4

🌐 Internet Detection

Browser periodically probes a public endpoint. If reachable, a warning is flagged on the dashboard.
