ABCD
Sprint 2.5 was re-scoped. Originally planned as manual security hardening (provision a low-priv OS user, hand-write iptables rules), it's now a migration to self-hosted Judge0 — its isolate-based containment and ENABLE_NETWORK=false default cover both gaps as a property of the new architecture. This pulls a Phase-3 item ("swap to Docker sandbox") forward into the MVP. It also adds a real dependency: Judge0 ships its own Postgres + Redis via docker-compose — fully separate from BYTEARENA's own SQLite DB, but Docker itself becomes a stated prerequisite.
Sprints 0–2 were built solo, before this 4-person split existed. They're included below fully detailed, attributed to the role each task would fall under, so the whole team has the complete history — not just what's left.
C and D's scope was deliberately widened beyond "sandbox support" and "documentation" — C now owns capacity planning, adversarial testing, and operational runbook groundwork; D now owns onboarding docs, participant-facing copy, error/empty states, and the full Day-Of Organizer Runbook. Both carry real, load-bearing MVP work, not lighter-weight support roles.
